# ResearchNotion 桌面端体验优化设计

## 目标

在不改变“本地优先、桌面优先、Dify Agent 可解释”的产品形态下，把现有聊天、论文库、阅读器和论文问答从可用页面整理成连续、稳定、可恢复的科研工作区。

## 设计方向

界面延续 Notion 的内容密度和 Codex 的工作区层次：浅色纸面、低对比边界、克制的冷暖渐变、图标优先、圆角不超过 8px。新增功能不通过说明文案占据界面，而通过状态、快捷键、菜单和即时反馈自然暴露。

## 九项优化

1. **稳定框架**：侧栏使用明确的最小/最大尺寸，主内容始终允许收缩；窄窗口切换为紧凑模式，消除偶发缩窄和内容挤压。
2. **恢复工作现场**：本地保存当前页签、最近对话、最近论文、展开文件夹、PDF 页码和缩放；无效记录自动回退，不阻塞启动。
3. **统一搜索**：`Ctrl+K` 和侧栏搜索入口打开统一搜索层，同时检索对话标题、论文标题和论文库名称，并直接跳转。
4. **对话树操作**：保留拖动排序，增加右键菜单、明确落点和边缘自动滚动；文件夹展开状态持久化。
5. **聊天连续性**：自动跟随最新消息；等待状态进入消息流；回答支持复制和失败重试；输入框自动增高但不改变整体布局。
6. **论文导入反馈**：支持把 PDF/Markdown 拖入当前论文库；显示单一、明确的导入进度和结果；重复文件和失败给出可操作提示。
7. **专业阅读器**：首次和容器变化时适合宽度；支持方向键翻页、专注模式；按论文恢复页码和缩放。
8. **论文 AI 侧栏**：宽度可调整；选中文本以可移除的上下文块呈现；每篇论文保留独立会话现场，切换后可继续追问。
9. **统一反馈与可访问性**：建立轻量通知层；连接状态可直接进入设置；补齐焦点、工具提示、禁用态、空状态和减少动态效果支持。

## 状态边界

- 数据库继续保存论文、对话和消息等业务数据。
- `localStorage` 仅保存可以丢失的界面偏好，统一通过 `workspacePreferences` 读写并进行版本校验。
- Dify 调用、Agent 工具和本地索引协议保持不变；本轮只改善其桌面端呈现与错误恢复。
- PDF 页码仍同步给本地 Agent 阅读状态，界面偏好只负责恢复用户视图。

## 失败与恢复

- 本地偏好解析失败时清除坏数据并使用默认值。
- 已删除的对话、论文或文件夹不会因为旧偏好导致空白界面。
- 异步操作失败保留用户输入，并提供就地重试，不显示 Electron IPC 原始错误前缀。
- PDF 渲染失败继续使用已提取文本作为降级阅读内容。

## 验证

- 纯状态逻辑使用单元测试覆盖坏数据、版本和回退。
- 聊天、搜索、论文库、AI 侧栏和阅读器使用 Testing Library 覆盖真实交互。
- 运行 TypeScript 检查、renderer 测试和构建。
- 在 Electron 中以普通窗口和窄窗口检查聊天、论文列表、PDF、侧栏与快捷键，并保存截图。
